# 订单提交与实收统计

## 日常操作

- 电脑开单默认确认已收款，按开单金额自动入账；无需填写另一个收款表单。请在开单前完成线下收款。
- 小程序下单立即扣减库存并占用优惠券，订单状态为“待提货”，收款状态为“未收款”。此时不计入销售收入或利润。
- 商家使用原提货核销操作，确认已收到优惠后款项并交付商品后，系统一次性登记实收。金额为订单原价减去实际优惠金额，无需手填。
- 全额优惠的订单实收为 0，核销时仍结转商品成本，可能产生负利润。
- 不调用微信支付。这些状态记录的是商家确认的线下收款，没有新增部分收款或手动改价流程。

## 取消与退款

- 未收款的未完成订单取消时恢复库存及优惠券，不产生收入或退款。
- 已登记收款的未完成订单只允许商家取消。取消确认中需要确认已线下退款，系统保存一笔负数退款流水，反向冲减实收和对应商品成本；原收款记录保留。
- 已核销、已完成订单仍不允许直接取消。未新增售后退货业务。
- 优惠券取消退回后保留原有效期；已过期的券不会自动延长。

## 报表口径

- `transactions.total`、`mini_orders.total`：优惠后应收订单金额；`received_total`：当前净已收金额；`paid_at`：首次收款时间，退款后仍保留。
- `sale_receipts`：每个商品销售行对应的不可变收／退款流水。正数收款、负数退款；唯一编号避免重复入账。
- 销售明细、销售总览、概览今日净实收、商家工作台今日净实收都按照流水发生时间统计。跨日退款在退款当日冲减，不修改过去某日的原收款。
- 利润 = 实收 − 销售时记录的商品成本；退款反向冲减。成本缺失的历史行不计入利润，并单独提示。
- 保留电脑／小程序来源与交付方式；库存和待提货统计仍按实际库存及订单状态计算。

## 历史迁移

`0011_receipts_submissions` 按店主明确选择，将所有未作废的历史销售按原销售行金额视为全额已收，以原创建时间补记收款流水。对应有效小程序订单同步标记已收。已取消、已作废销售不补记收入。上线前应使用 `deploy/backup.sh` 备份。

## 防重复提交

- 两端在发送开单请求前持久保存 `request_key` 及完整原始提交内容。超时、网络中断或服务端异常后保留，不因为刷新页面或重新登录而生成新编号。
- 小程序按服务地址、AppID、登录模式、客户 ID 隔离保存；电脑端按站点及管理员 ID 隔离保存。结果待确认时显示核对入口，先核对／重试原单，再开新单。
- 小程序的查询接口按当前用户限定订单归属。重试使用原商品、数量、优惠券等内容；相同编号更换内容会被拒绝。
- 服务端锁与数据库唯一约束共同保证同一提交只创建一笔订单、扣一次库存、用一次券、记一次收款。同一购物车在完成后再次主动下单属于新的订单。
- 修改后的开单接口要求携带 `request_key`。部署后电脑需强制刷新，小程序需重新编译并上传体验／正式版本；旧版本缺少字段时会被拒绝，不会静默创建重复订单。
