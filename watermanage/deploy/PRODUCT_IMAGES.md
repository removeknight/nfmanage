# 商品图片

## 操作方式

店主或副店长登录网页后台，在「商品库存」找到商品，点击「设置图片」。选择照片后可预览，点击「保存图片」上传；已有照片可更换或移除。新增商品先保存，再设置图片。在售和已下架商品均可维护图片。

支持 JPG、PNG、WebP，单张最大 5MB、2000 万像素。建议使用品牌规格相符的白底正方形商品照。服务端会识别实际图片格式、更正照片方向，将最长边缩至不超过 1024 像素，并转换为去除元数据的 JPEG。透明区域填充白色，不裁切商品。

保存时显示上传百分比，传输完成后显示等待服务器保存。最多等待 60 秒，可点击「停止等待」恢复操作。网络超时或停止等待并不代表服务器已撤销保存，重试前请刷新商品列表确认当前图片。

网页商品卡片和小程序选购页共用 Product.image_url。小程序在页面可见时通过现有轮询更新；图片加载失败时显示占位图，并稍后重试。每次更换生成新文件地址，避免浏览器仍显示旧缓存。图片设置操作写入中文操作日志。

## 存储与部署

- 使用现有 image_url 字段，无需数据库结构迁移。
- 后端增加 Pillow 依赖，部署时安装 backend/requirements.txt。
- 生产环境 UPLOAD_DIR=/var/lib/watermanage/uploads；图片保存在 products 子目录。目录独立于 Git，更新代码不会覆盖图片。
- 本地开发未设置 UPLOAD_DIR 时使用项目 uploads 目录，已加入 Git 忽略。
- 图片读取地址为 /api/media/products/<随机文件名>.jpg，供客户公开读取；上传和移除接口要求店主或副店长权限。
- Nginx client_max_body_size 设为 6m，应用仍严格限制上传文件不超过 5MB。
- 小程序将相对图片地址拼接至 apiBaseUrl，上线时与 API 一同使用配置好的 HTTPS 域名。

安装脚本已包含持久目录、Supervisor 环境变量和 Nginx 大小配置。已有部署升级时，应先安装依赖、设置并传入 UPLOAD_DIR，再重启 API 和更新网页构建。不要仅修改 .env 后重启旧的 Supervisor 进程，需同步它的 environment 配置。

deploy/backup.sh 会同时产生数据库 dump 和图片 uploads.tar.gz。恢复数据库后，还需将对应图片包还原到相同 UPLOAD_DIR（图片包只包含该目录内的文件）。数据库中仅存地址，单独恢复数据库不会恢复照片。

小程序代码需重新编译并生成新的真机调试码；体验版需重新上传代码包。
